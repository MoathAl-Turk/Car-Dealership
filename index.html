Car Dealership Software Architecture

A comprehensive object-oriented design project developed at Princess Sumaya University for Technology.

Team: Moath Al-Turk, Ehab Alhattab, Mohammad Abu Nahleh, Abdelrahman Qawaqzeh, Hamzeh Naji

1. System Architecture & UML Design

The core of this project was designing a scalable system using strict SOLID principles to manage car manufacturing, options, ordering, and customer notifications.

2. Applied Design Patterns

  • Factory Pattern: Used within the CarFactory class to isolate the creation of car instances, ensuring the purchasing flow remains intact if new brands are added.
  • Decorator Pattern: Utilized the CarOptionDecorator abstract class to dynamically add features (like Heated Seats or a Panoramic Sunroof) to a car, calculating the total price without altering existing structures.
  • Strategy Pattern: Implemented the PaymentStrategy interface to allow interchangeable transaction methods (Cash or Credit Card) at checkout.
  • Observer Pattern: Created an OfferPublisher to maintain a loosely coupled system that broadcasts updates to registered Customers when new deals become available.

3. Human vs. AI Architecture Comparison

As part of the engineering analysis, we generated a secondary UML model using an AI tool to evaluate structural convergence and architectural trade-offs.

While both designs organically converged on the exact same four design patterns, key differences emerged in tax handling. Our team utilized a constant TAX_RATE inside the Order class, whereas the AI isolated the tax logic into a separate TaxCalculator class. This highlights the architectural trade-off between strict adherence to the Single Responsibility Principle and the risk of over-engineering simple computations.
